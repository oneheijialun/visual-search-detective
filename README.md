# 眼力侦探社

工程心理学作业二。使用闪烁式变化觉察任务，比较无提示、文字提示、图形提示和误导提示下的视觉搜索表现。

## 打开实验

在本机试玩时，双击 `visual-search-detective-preview.html`。文件内置脚本、样式和图片，试玩记录单独保存在本机。首页的「预览结果页」使用示例数据。完成正式试次后，个人结案报告会显示实际作答结果。

使用完整源码时，右键点击 ZIP 并选择「全部解压」，再进入解压后的 `dist` 文件夹，双击 `index.html`。正式收数可把整个 `dist` 目录部署到静态 HTTPS 主机。也可以在项目目录运行以下命令，再打开 [本机实验](http://127.0.0.1:8000/)。

```sh
python -m http.server 8000 --bind 127.0.0.1 --directory dist
```

实验者入口在首页右上角，也可访问 `?view=data`。本地记录随浏览器、设备和站点地址而异。同一设备建议全程使用同一个地址。跨设备招募时，可用实验者页的不同分配链接，并集中从课程平台下载数据，或收集参与者下载的本网页 JSON 后导入。

## 统一招募与报名信息

- 知情同意页填写校内或校外身份、性别和年龄。校内填写学号，校外直接选择校外。报名信息暂存在当前标签页。参与者可在结案报告单独下载报名信息，并自行私下交给主试核对。匿名编号可用于和作答结果对应。
- GitHub Pages 提供统一招募入口。点击「同意并继续」时，浏览器在本机随机抽取一套试次方案。不同参与者可能抽到同一方案。完成后，课程平台接收匿名试次数据。
- 运行 `node tools/build-standalone.cjs index.html` 生成发布版。GitHub Pages 从 `main` 分支的根目录发布 `index.html`。

## 实验设计

- 被试内设计。每名参与者完成 A 无提示、B 文字提示、C 图形提示和 D 误导提示各两轮。四类室内场景各两套，练习场景单独使用。
- 正式图对来自各自的一份固定 SVG 底图，每对只有三个局部图层发生变化。图形提示采用场景外的单色物品图例。B 和 C 提供相同的物品类别。D 的三个文字提示对应场景内保持不变的物品。
- 默认中央注视 500 ms、提示 3000 ms。无提示试次在提示阶段保持中央十字。之后按图 A 500 ms、空白 100 ms、图 B 500 ms、空白 100 ms 循环。正式试次限时 120 秒，练习限时 60 秒。
- 分配采用四行 Williams 条件顺序与四种图片轮换，共 16 个方案。每个方案中，各条件有两个不同场景，全部图对恰好出现一次。使用统一招募链接时，每次参加独立随机抽取一个方案。实验者也可用 `?slot=1` 至 `?slot=16` 手动分配。每个浏览器自动生成五位编号并检查本地重复。
- 浏览器动画帧负责呈现，使用 `performance.now()` 从首张正式刺激进入画面时开始计算搜索时间。完成一个 A—空白—B—空白才计入完整循环。浏览器刷新率会量化呈现时间，JSON 记录每个已结束阶段的实际时长和最大帧间隔。
- 切换到后台或在试次中打开退出窗口会中断该轮。继续时从注视阶段重新开始，保留有标记的中断记录。刷新页面后也可继续，刷新中断仅保留当时已存下的试次标识。分析时可按重启次数和帧间隔筛查。

## 收数设置

编辑 `dist/config.js` 可调整时间、图片分组、条件顺序、练习图、提交开关及接口参数。更改正式设计时同步递增 `studyVersion`，以区分不同版本的记录。更新单文件版时请重新生成该文件。重新部署后再发参与链接。

- 项目码为 `GVFNJG`，课程平台的实验名称为 `visual_search_flicker`。
- 每位参与者完成后提交一次 JSON 到 [注意实验室作业二接口](https://attention-lab-production.up.railway.app/api/hw2/submit)。顶层字段是 `project`、`experiment`、`participant`、`condition` 和 `trials`。组内实验的顶层 `condition` 留空，各试次通过 `cond` 标记 A–D。`rt` 是搜索时长的整数毫秒，`correct` 表示是否找齐三个目标。请求还附带逐试次明细。
- 下载密钥只在课程平台使用。网页源码仅含项目码。课程平台的收录字段和跨域许可由平台管理。正式数据以参与者实际提交后平台出现的新记录为准。
- 记录先保存在浏览器。服务器明确拒绝时，实验者可在详情页重试。网络超时或响应不明时，先到课程平台检查同一个匿名编号，避免重复记入。离线测试可把 `upload.enabled` 设为 `false`，正式发放前按需恢复。
- WebGazer 默认关闭。启用时需自行放置本地构建文件至 `dist/vendor/webgazer.js`，在配置中打开开关，使用支持摄像头的安全来源，并由参与者单独同意。估算坐标只进入本地 JSON。未做专门的视线校准时，这些坐标仅适用于探索性检查。[WebGazer 官方文档](https://webgazer.cs.brown.edu/)

## 导出与分析

CSV 每行是一条正式试次。JSON 同时保留分配方案、配置、试次、相位计时、逐次点击、中断和提交状态。练习完成标记用于恢复流程。正式试次表与课程提交均排除练习。浏览器的逐试次导出是完整记录的备份。

| 字段 | 含义 |
| --- | --- |
| `total_rt_ms` | 首张刺激到找齐三个目标的用时。超时记上限，分析完成用时时应单独处理 |
| `first_hit_rt_ms` 等 | 每次首次命中相对刺激开始的时间 |
| `cycle_count`、`a_views`、`b_views` | 完整循环数和两个画面的分别呈现次数 |
| `target_accuracy` | 找到的不同目标数 ÷ 目标总数 |
| `click_accuracy` | 命中 ÷（命中＋误点）。空白点击和重复命中单独记录 |
| `clicks` | 归一化坐标、原图坐标、时间、所见相位、判定、目标 ID 和设备输入类型 |
| `restarts` | 该试次在成功记录前的重启次数 |

### 收数前预测

讨论草案供作者核对并在收数前用自己的表述提交。预期有效提示比无提示更快，误导提示可能延长搜索时间并增加循环次数。图形与文字的差异应报告方向和大小。可先汇总每位参与者在各条件下的完成用时、找齐率、目标发现率和循环次数，再做配对的描述性比较。

### 结果与讨论

本项目交付时尚未采集参与者数据。完成收数后，在此记录有效样本数、各条件指标、超时与中断的处理方式，并讨论图对难度、条件顺序及显示设备差异。已核对每对图的共用底图和三个局部图层。变化难度仍需实际参与者数据评估。

## 开发与验证

纯 HTML/CSS/JS，运行无需安装依赖。使用 Node.js 20 或更新版本可重新生成 SVG 和运行检查。

```sh
node tools/build-stimuli.cjs
node tools/build-standalone.cjs visual-search-lab.html
node tools/build-standalone.cjs visual-search-detective-preview.html --preview
node --test tests/core.test.cjs
node tests/browser.cjs ../visual-search-browser-qa
```

最后一个命令生成独立的浏览器测试目录。用浏览器打开测试目录的 `index.html`，页面会自动运行短时程试次，用模拟接口检查提交。生成目录不用于招募。
